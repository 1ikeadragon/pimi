# I18n

The client UI is English only. Do not add languages, a language setting, or locale detection.

Client UI copy lives in `packages/app/src/i18n/resources/en.ts`. `t()` and `useTranslation()` stay as the access path to that file; there is one resource and no per-locale parity to maintain.

## Adding Copy

Add the key to `en.ts` and use it through `useTranslation()` in components and hooks, or `i18n.t(...)` from `@/i18n/i18next` in pure helpers. Keep keys grouped by product surface, not component mechanics. Pass translated text into UI primitives; low-level primitives such as `<Button>` do not import translation state unless they own the text they render.

Do not route agent output, daemon output, terminal contents, file paths, provider names, model names, command names, user-authored text, code blocks, logs, or raw protocol/server error text through `t()`.

## Forge-Variant Copy

Brand names ("GitHub", "GitLab"), the PR/MR initialism and number prefixes are interpolated into one key (`"Refresh git and {{brand}} state"`) from `getForgePresentation`. Sentences with the full change-request noun use the i18next `context` mechanism: the base key carries the pull-request wording and an `_mr` sibling carries the merge-request wording. Call sites pass `t(key, { context: getForgePresentation(forge).changeRequestContext })`.
